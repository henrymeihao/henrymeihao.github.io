# 首页保持全文连续流，用「最新 20 篇」上限代替无限滚动

## 触发
用户原话："首页就弄成全文连续流，但是你要考虑一下无限滚动的问题"。

## 决定
首页只渲染最新 `site.homeLimit`（20）篇的全文，超出时在末尾放「更早的文章 →」，指向 `/writing/`。更早的文章仍可通过侧栏、搜索和各自的 `/writing/slug/` 访问。按现在的体积估算（7 篇约 64KB，压缩后约 15KB），20 篇约 180KB，压缩后约 45KB。

## 放弃的备选
- 滚动到底时用 JavaScript 追加更早的文章（无限滚动）：浏览器自带的页内查找只能搜到已加载的部分；`reading.js` 靠 DOM 位置恢复阅读位置，追加内容后位置会漂移；吸顶栏和侧栏当前文章的判断也要重写。这些复杂度现在换不到收益。
- 对每篇文章加 `content-visibility: auto`：离屏文章的高度只是估算，会让恢复阅读位置和吸顶栏的位置判断出现偏差，而且绘制隔离会裁掉文章末尾滑出的吸顶栏。
- 不设上限：文章数增长后页面体积和首次渲染会无限增长。

## 后果
- 第 21 篇起，首页不再显示全文，读者需要点「更早的文章」。当前只有 7 篇，现在没有可见变化。
- 若上限仍嫌小或篇数增长到数百篇，再考虑构建期分页（`/page/2/`），仍是静态页面。
