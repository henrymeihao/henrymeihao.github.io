# 决策记录生命周期

本闭环要求三个语义阶段，但不要求特定的文件名、目录或状态词。

| 语义阶段 | 必需含义 | 可能的宿主形式 |
|---|---|---|
| Working | 未实现、部分实现或仍在变化；负责 Problem、Proposal、Alternatives、Acceptance、Risks | Spec、RFC、提案、design doc、ADR 草案 |
| Current | 决策已被源码、证据和当前文档反映；负责 Decision、Alternatives、Consequences、Verification | ADR、决策记录、已实施的设计、已交付的 RFC |
| Declined | 提案经过评估但未被采纳；理由仍有价值 | 被拒的 RFC、被否决的提案、已关闭/已拒绝的决策 |

不要机械地对应状态词。在某些 ADR 体系中，`accepted` 只表示已批准而未实现。对本闭环而言，只有仓库的实际实现、证据和当前文档收敛一致后，记录才算 Current。

## 工作提案

规模较大且未实现或部分实现的变更记录：

```markdown
## Problem
## Proposal
## Alternatives considered
## Acceptance criteria
## Risks
```

Problem 的成立不依赖提案。替代方案必须真实。验收描述可观察的完成状态。风险包括可能的失败模式和有意放弃的能力。

## 当前决策

交付后，把提案改写为当前事实：

```markdown
## Problem
## Decision
## Alternatives considered
## Consequences
## Verification
```

Verification（或宿主仓库等价的持久证据映射）记录交付后仍具权威性的验收义务和直接证据。可选的现在时 Testing、Deferred 或 Related 章节是允许的。不要在 Current 记录中留下未来计划或验收清单。路径、符号、默认值、机制等事实性内容变动时保持更新；但不要把决策改写成它的反面。

当一个文件同时承载两个阶段时，改写它的标题和语义章节。只改状态词的转换是无效的，即使实现和测试都通过。

改写会丢掉工作阶段经过的那些方向。决策日志必须已经保存了它们，见 [decision-journal.md](decision-journal.md)。

如果宿主使用分开的提案文件和决策文件，把它们互相链接，并让其中一个产物成为当前理由的归属。不要维护两份完整且相互竞争的现状描述。

## 被否决的提案

只在被评估的提案和简要否决理由还能防止一个可能重复的错误时保留它们。否则按仓库政策删除。

## 替换与合并

替换是决策之间限定范围的关系，不是第四个语义阶段。

### 活跃修订

在同一个未完成的 PR 或变更栈内，当已接受方向变化时直接修订工作提案。不要为每个评审发现或实现中的发现建立永久替换链。每次被接受的方向变化都追加一条日志，这样原地修订就不是旧方向的唯一痕迹。读 [requirement-change.md](requirement-change.md) 和 [decision-journal.md](decision-journal.md)。

### 局部替换

当早先的决策仍负责某个有效边界时：

- 两份决策都保持 Current；
- 互相链接；
- 注明替换记录改变了哪些条款；
- 注明早先的归属记录保留哪些条款；
- 保持其余当前事实准确。

### 完全替换

只有当前归属记录保留了旧决策每一项独有内容之后，才合并、退役或删除它：

- 理由和真实的替代方案；
- 后果和放弃的能力；
- 验证义务和已点名的覆盖缺口；
- 重新引入条件；
- 入站引用。

Git 历史不能成为这些决策价值的唯一存留副本。

### 已使用 `superseded` 状态的宿主仓库

宿主已有的生命周期约定使用该词时就遵循它。但仍要求存在当前的替换归属记录、交叉链接、明确的替换范围和被保留的理由。兜底约定不引入 `superseded/` 目录，也不要求该状态。

## 完全移除

只有当某项能力在生产源码、注册/配置、schema、持久/线上传输格式、迁移、兼容行为、当前文档和受支持行为测试中全部缺席时，新增决策才能被移除决策完全吸收。只移除一种传输方式、默认值、实现或呈现方式仍属于局部替换。

## 历史归档

归档是可选的，不是当前语义阶段。使用仓库既有的历史记录约定。只有真实的保留需求出现后才创建归档机制。

当决策的替代方案、归属边界、反向保证、持久语义、安全规则、重新引入条件或覆盖缺口仍能指导未来工作时，让它保持 Current。历史记录永远不凌驾于当前源码、契约或文档之上。
